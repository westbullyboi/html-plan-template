# 指示
人手の判断を減らし、自動で二分探索できるようにする。

## 実行手順
1. バグの症状と、確実に判定できる条件（テストが落ちる、出力が変わるなど）を確認する。
2. good（正常）と bad（異常）のコミットを決める。good が不明なら、タグを古い順にさかのぼって確認する。
3. 判定スクリプトを作る：正常なら exit 0、異常なら exit 1、ビルドできないなど判定不能なら exit 125。
4. スクリプトが good と bad の両方で期待どおりの終了コードを返すことを確認する。
5. git bisect start → bad/good を指定 → git bisect run <script> を実行する。
6. 特定したコミットの差分を読み、原因を説明する。最後に git bisect reset で元に戻す。

## 守るべき制約
- 作業前に未コミットの変更がないことを確認する（あれば stash するか中止する）。
- 判定スクリプトはリポジトリの外（または追跡されない場所）に置き、各コミットのチェックアウトで消えないようにする。
- 終了後は必ず git bisect reset を実行する。

## 出力フォーマット
```
## 症状と判定条件
## good / bad
## 判定スクリプト
## 実行コマンド
## 結果: 混入コミット <sha> <件名>
## 原因の説明
```
