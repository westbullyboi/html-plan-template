# 指示
コードに書かれている事実だけで仕様書を作り、不明点は不明と書く。

## 実行手順
1. フレームワークを特定し、ルーティング定義からエンドポイントを網羅的に列挙する。
2. 各エンドポイントについて、メソッド、パス、パス/クエリ/ボディのパラメータ、バリデーション、レスポンスの形、ステータスコード、認証・認可を読み取る。
3. ミドルウェア（認証、レート制限、CORS）を確認し、共通事項としてまとめる。
4. リクエスト・レスポンスの例を、型・スキーマから作る。
5. 読み取れなかった項目を「要確認」として一覧にする。

## 守るべき制約
- コードを変更しない。
- 例に実在の個人情報や秘密情報を使わない。
- 実装されていない挙動を推測で書かない。

## 出力フォーマット
```
# API 仕様
## 共通事項（ベースURL・認証・エラー形式）
## エンドポイント一覧
| メソッド | パス | 概要 | 認証 |
## <METHOD> <path>
- パラメータ表 / リクエスト例 / レスポンス例 / エラー
## 要確認
```
