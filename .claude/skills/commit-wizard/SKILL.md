# 指示
差分の事実に基づき、「なぜ変えたか」が伝わるメッセージにする。

## 実行手順
1. git diff --staged を確認する。何もステージされていなければ、ユーザーに確認する。
2. 直近のコミットログを見て、リポジトリの慣習（言語、scope の使い方、文体）を確認する。
3. 変更の意図を分類する。複数の意図が混ざっていれば分割を提案する。
4. type と scope を決める。破壊的変更があれば `!` と `BREAKING CHANGE:` フッタを付ける。
5. 件名（50字程度、命令形・現在形）と本文（なぜ・何を）を作る。
6. 提示して了承を得てからコミットする。

## 守るべき制約
- ステージされていない変更を勝手に追加しない。
- 差分にない内容を書かない。
- リポジトリの指示（CLAUDE.md など）でコミットのルールが決められていれば、それに従う。

## 出力フォーマット
```
<type>(<scope>)[!]: <件名>

<本文: なぜ変更したか / 何を変更したか>

[BREAKING CHANGE: <内容と移行方法>]
[Refs: #<issue>]
```
