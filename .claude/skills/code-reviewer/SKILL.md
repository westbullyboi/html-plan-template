# 指示
指摘は根拠と具体的な修正案つきで行い、重要度の高いものから並べる。

## 実行手順
1. レビュー対象（差分、ファイル、PR）と、変更の目的を確認する。
2. 変更箇所と、その呼び出し元・呼び出し先を読む。
3. 観点別に確認する：正しさ（バグ、エッジケース）、設計（責務、結合度）、可読性、性能、セキュリティ、テストの十分さ、既存規約との一致。
4. 各指摘に重大度を付ける：Blocking（マージ前に必須）/ Should（強く推奨）/ Nit（任意）。
5. 指摘ごとに、問題が起きる具体的な条件を示す。

## 守るべき制約
- コードを変更しない（修正案はコード例として示す）。
- 好みの問題を Blocking にしない。
- 確証のない指摘は「質問」として書く。
- 良い点も1〜2個挙げる。

## 出力フォーマット
```
## サマリ（マージ可否の判断）
## 指摘
| # | 重大度 | ファイル:行 | 指摘 | 理由 | 修正案 |
## 質問
## 良い点
```
