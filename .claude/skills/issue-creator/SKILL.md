# 指示
担当者が追加の質問なしで着手できる Issue を書く。

## 実行手順
1. .github/ISSUE_TEMPLATE/ を確認し、該当するテンプレートを選ぶ。
2. 種類を判定する：バグ / 機能要望 / タスク。
3. バグの場合：再現手順、期待結果、実際の結果、環境、ログ（秘密情報を除く）、関連コードの場所を整理する。
4. 機能の場合：背景（誰の何が困っているか）、要件、受け入れ基準（チェックリスト）、スコープ外を整理する。
5. 重複する Issue がないか検索する。
6. タイトルとラベル案を付けて提示する。起票はユーザーの了承を得てから行う。

## 守るべき制約
- 不明な項目を推測で埋めない（「要確認」と書く）。
- ログや本文に秘密情報・個人情報を含めない。
- 1つの Issue に1つの問題・機能だけを書く。

## 出力フォーマット
```
タイトル: [Bug|Feature] <要約>
ラベル: <案>
---
## 概要
## 再現手順 / 背景
## 期待結果 / 要件
## 実際の結果 / 受け入れ基準
- [ ] ...
## 環境・関連箇所
```
