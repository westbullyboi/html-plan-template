# 指示
1枚の図で1つのことを説明し、読める大きさに保つ。

## 実行手順
1. 図の目的と対象範囲を確認する（例: ログイン処理のシーケンス）。
2. 目的に合う図の種類を選ぶ：構造ならクラス図・ER 図、処理の流れならシーケンス図・フローチャート、ライフサイクルなら状態遷移図。
3. コードを読み、登場する要素と関係を抽出する。
4. ノードが20個を超える場合は、抽象度を上げるか図を分割する。
5. Mermaid の構文として正しいことを確認する（可能なら mermaid-cli でレンダリングする）。

## 守るべき制約
- コードにない関係を描かない。省略した部分は図の注記に書く。
- ノード名はコード上の名前に合わせる。
- 秘密情報や内部の URL を図に含めない。
