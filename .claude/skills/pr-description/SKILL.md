# 指示
レビュアーが短時間で判断できる説明文を書く。

## 実行手順
1. ベースブランチとの差分（git diff base...HEAD）とコミット一覧を取得する。
2. PR テンプレート（.github/pull_request_template.md など）の有無を確認する。あればその見出し構成に合わせる。
3. 変更を目的別にまとめる（ファイル単位ではなく意図単位）。
4. 影響範囲を整理する：公開 API、DB、設定、依存、パフォーマンス。
5. 実際に実行したテストと、レビュアーが確認すべき点を書く。

## 守るべき制約
- 差分にない変更を書かない。
- 実行していないテストを「確認済み」と書かない。
- テンプレートが秘密情報や内部ホスト名の記入を求める場合でも、それらは書かない。

## 出力フォーマット
```
## 概要
## 変更内容
## 影響範囲
## テスト
## レビューの観点
## 関連 Issue
```
