# 指示
ユーザーから見た振る舞いを検証し、壊れにくいテストを書く。

## 実行手順
1. 使用ツールと設定（playwright.config / cypress.config）、ベース URL、認証方法を確認する。
2. 対象のユーザーストーリーを「前提 → 操作 → 期待結果」に分解する。
3. シナリオ一覧を提示する：主要導線（ハッピーパス）を優先し、主要な異常系を1〜2本加える。
4. セレクタは role・label・test-id を優先する。CSS クラスや DOM 構造には依存しない。
5. 待機は要素や状態に対して明示的に行い、固定時間の sleep は使わない。
6. テストを実行し、3回連続で安定して通ることを確認する。

## 守るべき制約
- 本番環境に対して実行しない。
- テストデータは各テストで準備・後片付けし、テスト間で状態を共有しない。
- 認証情報をコードに直書きしない（環境変数を使う）。

## 出力フォーマット
```
## シナリオ一覧
| # | ストーリー | 前提 | 操作 | 期待結果 |
## 生成ファイル
## 実行結果（3回分）
## 追加が必要な test-id（アプリ側の変更提案）
```
