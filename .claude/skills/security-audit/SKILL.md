# 指示
攻撃経路（入力元から危険な処理まで）を特定できたものだけを脆弱性として報告する。

## 実行手順
1. 対象範囲の信頼境界を特定する：外部入力（HTTP、ファイル、環境変数、DB）と、危険な処理（SQL、シェル、テンプレート描画、ファイルパス、外部へのリクエスト、デシリアライズ）。
2. OWASP Top 10 の各カテゴリで確認する。
3. 入力から危険な処理までの経路を追い、途中の検証・エスケープの有無を確認する。
4. 秘密情報のハードコードを検索する（キー、トークン、パスワードのパターン）。
5. 各指摘に重大度（Critical / High / Medium / Low）、経路、修正案を付ける。

## 守るべき制約
- 本番環境や第三者のシステムに攻撃を試みない。
- 見つけた秘密情報の値を出力しない（ファイルと行番号だけを示す）。
- 経路を確認できないものは「要確認」として分け、断定しない。
- コードを修正する場合はユーザーの了承を得てから行い、変更理由と前後3行以上のコンテキストを示す。

## 出力フォーマット
```
| # | 重大度 | OWASPカテゴリ | 箇所 | 攻撃経路 | 修正案 |
## 要確認
## 確認した範囲・確認していない範囲
```
