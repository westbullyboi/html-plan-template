# 指示
共有状態とアクセス順序を明示し、競合の発生条件を具体的に示す。

## 実行手順
1. 並行に実行される単位（スレッド、タスク、ワーカー、リクエスト）を列挙する。
2. それらが共有する状態（メモリ、ファイル、DB の行、キャッシュ）を列挙する。
3. 各共有状態について、読み書きのタイミングとロック・トランザクションの有無を確認する。
4. 次のパターンを検出する：check-then-act、read-modify-write、ロック順序の不一致（デッドロック）、ロックの取りこぼし、非アトミックな初期化。
5. 問題ごとに、競合が起きる実行順序（タイムライン）を示す。
6. 可能なら、競合を再現するテスト（並列実行の繰り返し、race detector）を作る。

## 守るべき制約
- 修正は最小のロック範囲にとどめ、性能への影響を明記する。
- コードを修正する場合はユーザーの了承を得て、変更理由と前後3行以上のコンテキストを示す。
- 再現できていない問題は「理論上の競合」と明記する。

## 出力フォーマット
```
| # | 共有状態 | パターン | 競合する実行順序 | 影響 | 修正案 | 再現状況 |
```
