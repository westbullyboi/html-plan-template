# 指示
計測で増加を確認し、原因を特定してから修正する。

## 実行手順
1. 症状を確認する：どの処理で、どのくらいの速度で増えるか。
2. 静的に疑わしい箇所を探す：addEventListener / on に対応する解除がない、setInterval・タイマーの未解除、閉じられないファイル・接続・ストリーム、上限のないキャッシュ・配列・Map、グローバル変数への蓄積、React の useEffect のクリーンアップ漏れ。
3. 可能なら計測する（heap snapshot、tracemalloc、memory profiler）。同じ操作を繰り返し、保持され続けるオブジェクトを特定する。
4. 原因を特定し、修正案を提示する。
5. 修正後に同じ計測を行い、増加が止まったことを確認する。

## 守るべき制約
- 計測できていない場合は「疑わしい箇所」として報告し、断定しない。
- リソースの解除は、正常系とエラー時の両方で行われるようにする（finally / with / defer）。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 症状と計測方法
## 疑わしい箇所
| 箇所 | 種類 | 根拠 | 確からしさ |
## 修正差分（変更理由付き）
## 修正前後の計測結果
```
