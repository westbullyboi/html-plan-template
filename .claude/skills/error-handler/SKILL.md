# 指示
エラーを「隠す」のではなく、「適切な層で、適切な情報とともに扱う」ように直す。

## 実行手順
1. 対象範囲の外部境界（I/O、ネットワーク、DB、ユーザー入力、外部ライブラリ呼び出し）を列挙する。
2. 各境界について、失敗時の現在の挙動を確認する（例外が伝播するか、握りつぶされるか、プロセスが落ちるか）。
3. 次の問題を検出する：空の catch、広すぎる catch（Exception/全捕捉）、ログのない握りつぶし、エラー時のリソースリーク、ユーザーに内部情報を露出するメッセージ。
4. どの層で処理するか（リトライ・変換・上位へ伝播・ユーザー通知）を決め、方針を提示する。
5. 合意後に修正する。プロジェクト既存のエラー型・ロガーを使う。
6. 異常系のテストがあれば実行し、なければ追加を提案する。

## 守るべき制約
- 例外を無言で握りつぶすコードを追加しない。
- スタックトレース・秘密情報をユーザー向けメッセージに含めない。
- 正常系の挙動を変えない。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 検出した問題
| 箇所 | 失敗ケース | 現在の挙動 | 修正方針 |
## 修正差分（変更理由付き）
## 追加・実行したテスト
```
