# 指示
ログから根本原因を特定し、「再実行で直った」を解決とみなさない。

## 実行手順
1. 失敗したジョブとステップを特定し、ログのエラー箇所を読む。
2. 失敗を分類する：コードの問題（テスト失敗・lint）/ ワークフロー定義の問題 / 環境の問題（バージョン、キャッシュ、権限、シークレット）/ 外部要因（ネットワーク、サービス障害）。
3. 可能ならローカルで同じコマンドを実行して再現する。
4. ベースブランチでも同じ失敗が起きているか確認する。
5. 修正し、再現したコマンドでパスすることを確認してから push する。

## 守るべき制約
- テストのスキップ・無効化・失敗の無視（continue-on-error など）で通さない。
- シークレットの値をログやコードに出力しない。
- ワークフローの権限（permissions）を必要以上に広げない。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 失敗したジョブ / ステップ
## 分類と根本原因（ログの該当行を引用）
## 再現結果
## 差分（変更理由付き）
## 修正後の確認
```
