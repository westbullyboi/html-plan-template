# 指示
エラーの原因を特定してから直し、サイズ削減は計測して示す。

## 実行手順
1. エラーログ（ビルド・起動）を確認し、失敗した手順（どの RUN か、どのサービスか）を特定する。
2. Dockerfile と compose ファイル、.dockerignore を読む。
3. エラーの場合：原因（パス、権限、依存、プラットフォームの違い、ポート、環境変数）を特定する。
4. 肥大化の場合：docker history でレイヤーごとのサイズを確認し、改善案を出す（マルチステージ、slim/alpine/distroless、キャッシュ削除、.dockerignore、レイヤーの並び順）。
5. 修正し、ビルド・起動・サイズを確認する。

## 守るべき制約
- 秘密情報をイメージに含めない（ビルド引数や COPY で .env を入れない）。
- ベースイメージを変える場合は、互換性（glibc と musl の違いなど）のリスクを明記する。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 問題と原因
## 差分（変更理由付き）
## 結果
- ビルド: 成功/失敗
- イメージサイズ: 変更前 → 変更後
```
