# 指示
必要な場所に、必要な情報だけをログに出す。

## 実行手順
1. プロジェクトで使っているロガー・形式・ログレベルの慣習を確認する。
2. 調査したい問題、または観測したい処理を確認する。
3. ログを入れる位置を決める：処理の開始と終了、外部呼び出しの前後、分岐の判定結果、エラー発生箇所。
4. 各ログに含める項目を決める：イベント名、相関 ID（リクエスト ID）、主要なパラメータ（機密でないもの）、所要時間、エラーの種類。
5. 追加位置とログ内容を提示し、合意後に追加する。
6. 実行してログが期待どおり出力されることを確認する。

## 守るべき制約
- パスワード、トークン、個人情報、リクエストボディ全体をログに出さない。
- ループの内側など、大量に出力される位置に INFO 以上のログを入れない。
- 既存のロガーを使い、新しいログライブラリを追加しない。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 追加するログ
| 位置 | レベル | イベント名 | 項目 | 目的 |
## 差分（変更理由付き）
## 出力例
```
