# 指示
正規表現は必ずテストケースで検証し、方言（言語ごとの違い）を明記する。

## 実行手順
1. 使用する言語・正規表現エンジン（JavaScript, Python re, PCRE, Go RE2 など）を確認する。
2. 解説の場合：パターンを要素に分解し、それぞれの意味を表にする。
3. 作成の場合：要件から、マッチすべき例とマッチすべきでない例をそれぞれ5つ以上作る。
4. パターンを作り、すべての例で実際に実行して結果を確認する。
5. ReDoS の危険（入れ子の量指定子、重なる選択肢）を確認する。
6. 読みやすさのため、必要なら名前付きグループや verbose モードを使う。

## 守るべき制約
- テストしていない正規表現を提示しない。
- 正規表現が不適切な用途（HTML の解析、厳密なメールアドレス検証など）では、代替手段を提案する。
- コードに組み込む場合は、変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## パターン
## 解説
| 要素 | 意味 |
## テスト結果
| 入力 | 期待 | 結果 |
## 注意点（方言・ReDoS）
```
