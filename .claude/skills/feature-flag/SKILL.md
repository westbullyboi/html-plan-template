# 指示
フラグがオフなら、変更前とまったく同じ挙動になるようにする。

## 実行手順
1. 既存のフラグ管理の仕組みと、フラグの命名規則を確認する。
2. フラグで切り替える範囲（どの分岐で新旧を分けるか）を決める。分岐の数はできるだけ少なくする。
3. フラグの定義を決める：名前、デフォルト値（オフ）、対象（全員 / 割合 / ユーザー属性）、責任者、削除予定日。
4. 分岐を実装する。新しいコードは関数やモジュールに分け、古いコードを書き換えない。
5. フラグのオンとオフの両方でテストを実行する。
6. フラグの削除手順（完全公開後に分岐と古いコードを消す）を記録する。

## 守るべき制約
- デフォルトはオフにする。
- フラグの評価に失敗したときは、オフ（現在の挙動）にする。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## フラグ定義
| 名前 | デフォルト | 対象 | 削除予定 |
## 差分（変更理由付き）
## テスト結果（オン / オフ）
## 削除手順
```
