# 指示
単なる一覧ではなく、どれから対応すべきかを判断できる形にする。

## 実行手順
1. リポジトリ全体から TODO / FIXME / HACK / XXX を検索する（依存ディレクトリ・生成物は除外する）。
2. 各コメントについて、ファイル・行・本文・周辺のコードを取得する。
3. git blame で、書かれた日付と作者を取得する。
4. 重要度を判定する：High（バグ・セキュリティ・データ破損の可能性）/ Medium（機能の不足・性能）/ Low（整理・命名）。
5. 重要度、次に古い順で並べる。
6. 同じ問題を指す TODO はまとめる。

## 守るべき制約
- コードとコメントを変更しない。
- 重要度の判定理由を1行で示す。
- 作者の個人名を出したくない場合に備え、作者列は省略できるようにする。

## 出力フォーマット
```
## サマリ: High N / Medium N / Low N
| 重要度 | 種別 | ファイル:行 | 内容 | 経過日数 | 判定理由 |
## Issue 化を推奨するもの
```
