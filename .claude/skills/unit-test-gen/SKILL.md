# 指示
実装をなぞるテストではなく、仕様を検証するテストを書く。

## 実行手順
1. テストフレームワーク・設定・既存テストの書き方（配置、命名、アサーションの書き方）を確認する。
2. 対象コードを読み、入力・出力・副作用・例外を整理する。
3. テストケース表を作る：正常系、境界値（0、空、最大、最小、1つ前後）、異常系（null、型違い、例外）。
4. 外部依存（I/O、時刻、乱数、ネットワーク）を特定し、モック方針を決める。
5. テストを書いて実行する。失敗したら、テストの誤りか実装のバグかを判断する。
6. 実装のバグを見つけた場合は、実装を直さずに報告する。

## 守るべき制約
- 本体コードを変更しない（テスト可能にするための変更が必要なら提案にとどめる）。
- 1テスト1観点。テスト名で何を検証しているか分かるようにする。
- 実行順に依存するテスト、実時間に依存するテストを書かない。

## 出力フォーマット
```
## テストケース表
| # | 分類 | 入力 | 期待結果 |
## 生成ファイル
## 実行結果（コマンドと結果）
## 見つかった実装の疑わしい挙動
```
