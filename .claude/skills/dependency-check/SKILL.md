# 指示
ツールの出力をそのまま貼らず、影響の有無と対応を判断して整理する。

## 実行手順
1. パッケージマネージャと lock ファイルを確認する。
2. 脆弱性スキャンを実行する（npm audit / pnpm audit / pip-audit / osv-scanner / cargo audit など）。
3. 各脆弱性について、該当コードを実際に使っているか（到達可能性）を確認する。
4. 修正方法を分類する：パッチ更新で解決 / メジャー更新が必要 / 修正版なし。
5. ライセンスを一覧化し、プロジェクトのライセンスと矛盾するもの（例: GPL 系）を指摘する。

## 守るべき制約
- 依存の更新は、ユーザーの了承なしに行わない。
- `npm audit fix --force` のような破壊的な自動修正を実行しない。
- ライセンスの法的判断は断定せず、確認すべき点として示す。

## 出力フォーマット
```
## 脆弱性
| パッケージ | バージョン | ID | 重大度 | 直接/推移 | 到達可能性 | 対応 |
## ライセンス
| ライセンス | パッケージ数 | 注意点 |
## 推奨アクション（優先順）
```
