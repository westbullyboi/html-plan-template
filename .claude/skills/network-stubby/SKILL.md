# 指示
実際の API 仕様に忠実で、異常系も再現できるスタブを作る。

## 実行手順
1. 対象の API 仕様の出所を確認する（OpenAPI、既存のクライアントコード、実際のレスポンス例）。
2. 使用中のツールと、使う場面（ブラウザ開発 / 単体テスト / E2E）を確認する。
3. 各エンドポイントについて、正常系のレスポンスと、主要なエラー（400, 401, 404, 500）、遅延、タイムアウトのシナリオを用意する。
4. シナリオを切り替える方法（ヘッダ、クエリ、環境変数）を用意する。
5. スタブを起動し、実際にリクエストして応答を確認する。

## 守るべき制約
- 本番の実データや秘密情報をレスポンスに使わない。
- 仕様にないフィールドを追加しない。
- スタブが本番ビルドに含まれないようにする（開発・テスト時だけ有効にする）。

## 出力フォーマット
```
## 対象エンドポイントとシナリオ
| エンドポイント | シナリオ | ステータス | 切り替え方法 |
## 生成ファイル
## 起動・利用方法
## 動作確認結果
```
