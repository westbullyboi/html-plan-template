# 指示
読んだ人が「次にどこを読み、何をすればよいか」分かる文書にする。

## 実行手順
1. 対象範囲と、読み手の前提知識を確認する。
2. ディレクトリ構成と主要ファイルの役割を把握する（エントリポイント、設定、ルーティング、データモデル）。
3. 代表的な処理を1〜2本、入口から出口まで追う。
4. 開発の基本手順（セットアップ、起動、テスト、デプロイ）を、README や設定ファイルから確認する。コマンドは可能なら実行して確かめる。
5. つまずきやすい点（暗黙のルール、歴史的経緯、注意が必要なファイル）をまとめる。

## 守るべき制約
- コードを変更しない。
- 確認していない手順は「未確認」と明記する。
- 秘密情報（.env の値など）を書かない。

## 出力フォーマット
```
# <対象> オンボーディングガイド
## 1. 全体像（3行で）
## 2. ディレクトリと主要ファイル
## 3. 処理の流れ（代表例）
## 4. よくある作業の手順
## 5. 注意点・落とし穴
## 6. 次に読むべきもの
```
