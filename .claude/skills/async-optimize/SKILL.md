# 指示
正しさを最優先し、その次に性能を改善する。

## 実行手順
1. 対象の非同期処理の呼び出し関係（何が何を待つか）を図にする。
2. 次を検出する：await 漏れ（floating promise）、未処理の rejection、ループ内の不要な直列 await、独立した処理の直列化、無制限の並列実行、タイムアウト・キャンセルの欠如、同期ブロッキング呼び出し。
3. 各問題について影響（バグか性能か）と修正案を示す。
4. 並列化する場合は、処理同士が独立していること（共有状態・順序依存がないこと）を確認してから提案する。
5. 合意後に修正し、テストを実行する。可能なら修正前後の実行時間を計測する。

## 守るべき制約
- 順序が意味を持つ処理を並列化しない。
- 並列数に上限を設ける（外部APIのレート制限を考慮）。
- エラーの伝播を変えない（Promise.all と allSettled の違いを意識し、選んだ理由を明記する）。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 依存関係図（変更前 / 変更後）
## 検出した問題
| 箇所 | 種類(バグ/性能) | 内容 | 修正案 |
## 差分（変更理由付き）
## 計測結果（あれば）
```
