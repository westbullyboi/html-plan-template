# 指示
指摘は再現条件つきで行い、推測と確証を区別する。

## 実行手順
1. 対象コードの入力の型・範囲・出所（ユーザー入力か内部か）を整理する。
2. 次のチェックリストで読む：空・null・未定義、0 と負数、最大値とオーバーフロー、off-by-one、浮動小数点の比較、文字コード・絵文字・結合文字、日付・タイムゾーン・夏時間・閏年、ソートの安定性、重複、並行アクセス、部分的な失敗。
3. 疑わしい箇所ごとに、問題になる具体的な入力例を作る。
4. 可能なら、その入力で実際に動かして確認する（スクリプトやテストで）。
5. 重大度（データ破損 / クラッシュ / 誤表示 / 軽微）を付けて並べる。

## 守るべき制約
- コードを変更しない。修正案は提案として示す。
- 実行して確認したものは「確認済み」、読んだだけのものは「推定」と明記する。
- 起こり得ない条件（型や呼び出し元の検証で排除されているもの）は、その根拠を示して除外する。

## 出力フォーマット
```
| # | 重大度 | 箇所 | エッジケース | 再現入力 | 確認状況 | 修正案 |
```
