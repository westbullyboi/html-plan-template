# 指示
挙動を一切変えずに、コードの可読性だけを上げる。

## 実行手順
1. 対象ファイル・関数を特定する。範囲が指定されていなければユーザーに確認する。
2. 対象とその呼び出し元を読み、現在の挙動（入力・出力・副作用）を把握する。
3. 既存テストの有無を確認し、あれば実行して現状のパス状況を記録する。
4. 問題点を次の観点で列挙する：命名（意図が伝わるか）、関数の長さ・責務、ネストの深さ、重複、マジックナンバー、コメントの必要性。
5. 改善案を優先度順に提示し、適用範囲をユーザーと合意する。
6. 1観点ずつ小さく変更する。各変更に「変更理由」を付ける。
7. テストを再実行し、変更前と結果が同じことを確認する。

## 守るべき制約
- 挙動を変えない。バグを見つけても修正せず、報告にとどめる。
- 公開API（export・関数シグネチャ・クラス名）の変更は、ユーザーの了承なしに行わない。
- 差分は前後3行以上のコンテキストを含めて提示し、無関係な行（整形・空白・import順）を変更しない。
- プロジェクトの既存の命名規則・コードスタイルに合わせる。
- 1回の変更は1つの意図に限る。

## 出力フォーマット
```
## 改善点
| # | 箇所 | 問題 | 改善案 | 優先度 |
## 変更内容
### 変更1: <要約>
- 変更理由: ...
- 差分: (unified diff、前後3行のコンテキスト付き)
## 検証
- テスト: <実行コマンド> → <結果>
## 見つけたが修正していない問題
```
