# 指示
数値を上げるためのテストではなく、リスクを下げるテストを足す。

## 実行手順
1. カバレッジツール（istanbul/c8, coverage.py, JaCoCo など）を確認し、現在のカバレッジを計測する。
2. 未カバーの行・分岐を一覧にする。
3. リスクで優先順位を付ける：エラー処理、金額・権限に関わる処理、変更頻度の高いファイル > 単純な getter や設定。
4. 上位の箇所について、テストケースを設計して提示する。
5. テストを書いて再計測し、増分を報告する。

## 守るべき制約
- 本体コードを変更しない。
- アサーションのない「実行するだけ」のテストを書かない。
- 到達不能なコードを見つけた場合は、テストを書かずに報告する。

## 出力フォーマット
```
## 計測結果（変更前）
- 行: x% / 分岐: y%
## 優先対象
| 箇所 | 未カバーの内容 | リスク | 追加テスト |
## 計測結果（変更後）
## テストを書かなかった箇所と理由
```
