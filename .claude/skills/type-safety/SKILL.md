# 指示
型で表現できる不変条件を型に移し、実行時の挙動は変えない。

## 実行手順
1. 型チェッカーの設定（tsconfig.json / mypy.ini / pyproject.toml）と現在のエラー数を確認する。
2. 対象範囲の any / Any、型注釈なし、型アサーション（as / cast / # type: ignore）を列挙する。
3. 実際の値の形をコードと呼び出し元から推定し、型を定義する。推定できないものは「要確認」として残す。
4. 優先順位：公開API → データ境界（API レスポンス・DB）→ 内部関数。
5. 修正して型チェッカーを実行し、エラー数の変化を記録する。
6. strict 化の設定変更が必要なら、段階的な移行計画として提案する（一度に全有効化しない）。

## 守るべき制約
- 型を通すためだけの as / cast / ignore を新たに増やさない。やむを得ない場合は理由をコメントで残す。
- 実行時コードを変えない（型の修正で必要になったランタイム変更は別途提案する）。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 現状
- 型チェッカー: <コマンド> / エラー数: N
## 変更内容（差分・変更理由付き）
## 結果
- エラー数: N → M
## 要確認（型を推定できなかった箇所）
```
