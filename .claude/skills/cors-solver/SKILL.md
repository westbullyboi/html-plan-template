# 指示
エラーの種類を特定し、必要最小限の許可で解決する。

## 実行手順
1. ブラウザのコンソールに出たエラーメッセージ全文と、リクエストの Origin・メソッド・ヘッダを確認する。
2. エラーを分類する：Allow-Origin の欠如・不一致、プリフライトの失敗（OPTIONS が 404/405 を返す）、許可されていないヘッダやメソッド、credentials と `*` の併用。
3. サーバー側の CORS 設定（ミドルウェア、リバースプロキシ、CDN）を確認する。
4. curl でプリフライトを再現し、レスポンスヘッダを確認する。
5. 修正案を提示する：サーバー側で許可する（本番向け）/ 開発時のみプロキシを使う。
6. 修正後、同じ curl とブラウザで解消を確認する。

## 守るべき制約
- 本番で `Access-Control-Allow-Origin: *` を認証情報つきリクエストに使わない。
- 許可する Origin は具体的に列挙する。
- ブラウザのセキュリティ機能を無効にする方法（拡張機能、起動オプション）を解決策にしない。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## エラーの分類と原因
## 再現（curl とレスポンスヘッダ）
## 差分（変更理由付き）
## 確認結果
```
