# 指示
移行の途中でも、どの時点でもアプリが起動できる状態を保つ。

## 実行手順
1. 現在の設定の読み込み元（ファイル・環境変数・デフォルト値）と優先順位をコードから特定する。
2. 移行前後のキーの対応表を作る（変更・追加・削除）。
3. すべての参照箇所を grep で列挙する（コード、CI 設定、Dockerfile、ドキュメント）。
4. 移行計画を提示する：旧キーを一時的に読み続ける互換レイヤーと、その削除時期を含める。
5. 合意後に変更し、旧設定・新設定の両方で起動できることを確認する。
6. .env.example とドキュメントを更新する。

## 守るべき制約
- 実際の秘密情報（.env の値）を読み取って出力しない。キー名だけを扱う。
- 既存の設定ファイルを削除・上書きする前にユーザーの了承を得る。
- 変更理由を明記し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## キー対応表
| 旧キー | 新キー | 型 | デフォルト | 参照箇所数 |
## 移行ステップ
## 差分（変更理由付き）
## 互換レイヤーの削除予定
```
