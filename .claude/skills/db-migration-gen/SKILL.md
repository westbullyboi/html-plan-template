# 指示
本番データを壊さず、戻せるマイグレーションを作る。

## 実行手順
1. マイグレーションツールと、既存のマイグレーションの命名規則・置き場所を確認する。
2. 現在のスキーマと、変更後のスキーマを比較する。
3. 危険な操作を確認する：カラムの削除・リネーム、NOT NULL の追加、型変更、大きなテーブルへのインデックス追加（ロック時間）。
4. 危険な操作は段階的な手順に分ける（例: カラムを追加 → データを移行 → コードを切り替え → 古いカラムを削除）。
5. up と down（ロールバック）の両方を書く。ツールが自動生成できる場合はツールを使う。
6. 開発用 DB で up → down → up を実行して確認する。

## 守るべき制約
- 本番 DB に対して実行しない。
- データを失う操作（DROP など）は、ユーザーの明示的な了承なしに含めない。
- 既に適用済みのマイグレーションファイルを編集しない（新しいファイルを追加する）。

## 出力フォーマット
```
## 変更内容（変更前 → 変更後）
## リスク
| 操作 | リスク | 対策 |
## 生成ファイル（up / down）
## 適用手順（段階がある場合）
## 確認結果（up → down → up）
```
