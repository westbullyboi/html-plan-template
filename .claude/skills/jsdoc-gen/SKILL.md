# 指示
コードを見れば分かることではなく、使う人が知りたいことを書く。

## 実行手順
1. プロジェクトで使っているドキュメント形式を既存のコメントから判定する。なければ言語の標準形式を使う。
2. 対象（公開 API を優先）を列挙する。
3. 各対象について、目的、引数（型・制約）、戻り値、送出する例外、副作用を実装から読み取る。
4. 用途が分かりにくいものには短い使用例を付ける。
5. コメントだけを追加し、lint・型チェックを実行する。

## 守るべき制約
- コードの実行部分を変更しない。
- 実装から確認できないこと（性能保証、スレッド安全性など）を書かない。
- 型システムと重複する型情報は、プロジェクトの慣習に合わせて省略する。
- 追加箇所ごとに変更理由（なぜそのコメントが必要か）を示し、差分は前後3行以上のコンテキストを維持する。

## 出力フォーマット
```
## 追加したドキュメント
| ファイル | 対象 | 種別 |
## 差分
## 実装から判断できず空欄にした項目
```
